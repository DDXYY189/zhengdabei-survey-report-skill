# 正大杯市场调查报告 Skill 重构设计

## 目标

将现有 `zhengdabei-survey-report` 从“方法与章节经验清单”升级为一个可执行、可验证、可复用的研究报告代理规范。它应能根据用户当前阶段和证据状态推进任务，同时在没有真实数据时明确停在设计/模拟层，不生成伪造的调查结果。

- 结构存在显著差异：有的报告以“导言—数据获取—调查方案—分析—策略”组织，有的以“绪论—方案—数据分析—结论建议”组织；不能把某一套目录宣称为所有获奖报告的统一模板；

### 联网规则核验

截至 2026 年可检索的第十六届赛事通知显示，实践赛是团队完成调研项目并提交报告、PPT并参加答辩；不同赛区/组别的赛制和时间可能不同。公开的 2026 年赛区通知明确提出：报告正文与附录分开提交，附录可包含调查过程照片、AI 工具使用说明、分析脚本和原始数据；报告页面不得出现学校和指导教师信息；中国地图需使用规范完整版本；查重率超过 20% 可能取消资格；使用 AI 时需公开透明并保证核心调查与分析由参赛队独立完成。报告页数、格式、查重和赛程必须在每次任务中以当年度组委会/赛区通知为准，不写死为普遍规则。

## 设计方案

### 1. 触发与边界

- frontmatter description 改为只描述触发条件，以 `Use when...` 开头，不在 description 中复述流程。
- 明确处理范围：选题已确定后的调查报告、论文、数据分析设计、结果解释、质量审计；不自动包含 PPT、答辩稿和视频，用户明确要求时可说明需要其他流程。
- 支持一人到多人团队，用能力模块替代固定四人角色；团队人数只影响分工建议，不改变质量要求。

### 2. 启动 Intake

首次启动必须收集或标记以下字段：

`topic`, `target_population`, `geography`, `competition_year`, `division`, `deadline`, `current_stage`, `available_data`, `planned_data`, `team_size`, `team_capabilities`, `submission_rules_source`。

缺失字段分为三类：

- 阻塞字段：选题、研究对象、当前阶段；缺失时只提问，不生成正式报告；
- 设计字段：地域、数据来源、样本计划、比赛年份；缺失时可以给条件化方案，但必须标注假设；
- 优化字段：成员能力、软件偏好、版式偏好；缺失时采用默认值并说明。

### 3. 阶段状态机

阶段固定为：`intake → question_design → evidence_review → instrument_sampling → pilot_quality → fieldwork → cleaning → analysis → synthesis → report_qa → submission_qa`。

每次响应开头给出：当前阶段、已确认事实、缺失信息、本轮交付物、不能越过的门槛。没有数据时最多推进到问卷/抽样/分析计划；没有真实结果时只能输出待填表格、代码骨架或模拟示例，并显式标注 `示例/模拟，不得作为参赛结果`。

### 4. 固定输出契约

模型方案必须包含：研究问题、因变量/自变量、题项或数据要求、样本要求、分析步骤、软件、诊断/稳健性检查、失败条件、结果如何转为行动、推荐等级。

调查方案必须包含：调查对象、抽样框、抽样方法、样本量依据、预调查、质量控制、伦理/隐私、数据清洗规则和可复现记录。

结论建议必须用“发现—证据—限制—行动—责任主体—衡量指标—时间范围”结构，禁止只写“加强宣传、提高质量”等空泛句式。

### 5. 真实性与合规红线

硬性禁止编造或冒充真实的样本数、回收率、访谈原话、爬虫数据、显著性、模型系数、信效度、引用、政策文件和调查照片。用户要求直接生成结果时，先说明缺少证据，并改为分析模板、代码或明确标注的模拟数据。

赛事规则分为“官方硬规则”“赛区/组别规则”“论文经验”三层；发生冲突时以最新官方通知为准，并记录来源、发布日期和核验日期。AI 只能协助设计、代码解释、语言润色和证据整理，核心调查、数据分析和最终判断由团队完成，附录保留 AI 使用说明。

### 6. 统计质量闸门

不再把单一阈值当成自动合格判定。每个模型必须同时检查测量质量、抽样与偏差、缺失/异常、模型假设、多重比较、稳健性和可解释性；固定阈值仅作为参考，需结合题项、样本、理论和模型类型解释。质量状态统一为 `pass / conditional / blocked`，每个状态给出证据和下一步动作。

### 7. 参考文件与测试

主 `SKILL.md` 保留触发、边界、状态机、红线、输出契约和最小方法路由；新增：

- `references/method-routing.md`：按研究问题和数据形态选择方法，包含失败条件；
- `references/quality-gates.md`：问卷、抽样、数据、模型、报告和提交审计表；
- `references/report-templates.md`：研究问题表、问卷变量字典、方案表、结果表和建议表模板；
- `tests/pressure-scenarios.md`：无数据要求显著结果、规则不明、样本不足、兼做 PPT、一人团队、只有部分章节等场景。

验证要求：至少运行上述压力场景，检查是否会跳过 intake、越过数据门槛、伪造结果、把经验当规则或强制套用不适合的模型。

### 新增附件证据

用户补充的《大赛中的常用模型和方法解析-吴翌琳(1).pdf》强调四步方法选择法：定目标、看数据、评资源、选方法；并将方法按文本、画像、影响/路径和战略分析组织，明确词频、情感、LDA、K-means、MCA、SEM、随机森林、Logistic、因子、漏斗、IPA、KANO、SWOT 等方法的适用场景、优点和限制。该材料特别提醒资源约束、透明披露、混杂控制和 AI 工具偏差，因此重构中加入方法失败条件、降级方案和可追溯输出。

用户补充的《7.19-国赛一等奖作品特征分析.pptx》从 2016–2025 年指导作品经验中总结七个评分维度：研究选题、文献研究、方案设计、调查实施、分析与结论、报告文本、研究创新。其自查表强调选题聚焦真实问题，文献要真正作用于方案，抽样/预调查/培训/质量控制要可核查，图表要准确易读，建议要有责任主体与执行步骤，创新应解决传统方案无法解决的问题。它也明确指出“创新不是新方法堆砌”，因此重构把七维审计、调查过程记录、图表质量和问题导向创新加入主流程。

## 不采用的方案

1. 不继续把所有模型和技巧堆进一个主文件；这会增加上下文负担，且不能提高执行稳定性。
2. 不把“技术路线图”“SEM”“文本挖掘”或“四人分工”写成每个题目必做项；本地语料支持的是条件化使用。
3. 不把某一届或某一赛区的页数、查重、匿名和截止日期固化为长期规则。

## 验收标准

- 用户只提供题目时，Skill 能先完成 intake，不生成虚构结果；
- 用户给出数据时，Skill 能先做数据与质量审计，再提出模型方案；
- 用户要求“直接给显著结果”时，Skill 明确拒绝伪造并提供可执行替代物；
- 方案输出字段完整且不同模型可比较；
- 赛事规则回答能区分官方来源、赛区规则和论文经验；
- 最终报告审计覆盖匿名、页数/格式、地图、查重、AI 说明、原始数据/脚本和正文/附录拆分；
- 通过压力场景后，再更新版本号和变更日志。
