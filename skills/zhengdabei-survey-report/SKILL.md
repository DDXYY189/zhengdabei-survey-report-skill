# 正大杯市场调查与分析报告

这是一个以证据为中心的研究报告工作流。核心不是堆砌模型，而是让“真实问题 → 可执行调查 → 可追溯数据 → 适配分析 → 有边界的结论 → 可落地行动”形成闭环。

## 适用范围与边界

适用于已确定选题后的：研究问题、文献与理论、抽样和问卷、访谈/文本资料、数据清洗、统计建模、结果解释、报告正文、附录和提交审计。

不默认处理选题开发、PPT、答辩稿、答辩视频。用户要求这些内容时，先完成报告范围内的工作，并说明需要单独的演示文稿工作流。

论文、培训课件和往届获奖作品只能作为经验材料，不能当作官方规则或本次调查证据。官方规则必须以当年度组委会和对应赛区通知为准。

## 启动协议

首次响应先填写 `references/report-templates.md` 的 Intake，并给出：当前阶段、已确认事实、缺失字段、本轮交付物、不能越过的门槛。

必需确认或明确标记的字段：

- 选题、研究对象/总体、地域与时间；
- 比赛年份、组别、赛区、截止时间和已核验规则来源；
- 当前阶段：方案、问卷、预调查、正式调查、清洗、分析、写作或提交审计；
- 已有数据、数据来源、计划获取的数据和数据真实性状态；
- 团队人数与能力模块：研究设计、数据/编程、视觉/排版、文稿/质控，可由一人兼任。

字段分级：

- **阻塞字段**：选题、研究对象、当前阶段。缺失时只提问，不生成正式报告；
- **设计字段**：地域、样本计划、数据来源、比赛规则。缺失时可给条件化方案，但必须标注假设；
- **优化字段**：软件偏好、版式偏好、团队分工。缺失时采用默认值并说明。

## 阶段状态机

按以下顺序推进，每次只跨越已经满足证据门槛的阶段：

`intake → question_design → evidence_review → instrument_sampling → pilot_quality → fieldwork → cleaning → analysis → synthesis → report_qa → submission_qa`

每个阶段都输出四项：`已完成事实 / 缺失证据 / 本轮产物 / 下一闸门`。

- 没有真实数据：最多推进到问卷、抽样和分析计划；
- 有数据但未完成清洗：先审计数据，不给正式模型结论；
- 有模型输出：先核对代码、变量编码、样本和诊断，再写结论；
- 已有部分章节：识别当前阶段，先补缺口，不从头覆盖用户已有材料。

## 真实性、学术与隐私红线

**禁止编造或冒充真实的**样本量、回收率、访谈原话、调查照片、爬虫数据、信度/效度、模型系数、p 值、置信区间、预测性能、引用、政策文件和“受访者表示”。

用户要求“直接给显著结果”时，明确说明缺少证据，并改为提供变量字典、分析方案、代码骨架、结果表模板或明确标注的模拟示例。模拟数据不得进入参赛正文。

调查发放、访谈、实地观察和核心分析必须由参赛队真实完成。AI 可用于方案讨论、代码解释、语言润色和证据整理，但不替代调查或最终判断。报告附录记录 AI 工具、用途、人工核验和修改范围；文本、图片、个人信息和平台数据遵守隐私、版权、平台条款和伦理要求。

## 方法选择原则

先问研究目标，再看数据，再评估资源，最后选最简单且可解释的方法。方法必须回答一个明确问题，且能说明结果如何转成行动。不要为了“高级”强行使用 SEM、机器学习、爬虫或文本挖掘。

完整方法路由、最小输入、诊断和失败条件见 `references/method-routing.md`。可用目标类别包括：

- 描述市场现状：频数、比例、集中趋势、离散程度、可视化；
- 解释影响因素：相关、回归、Logit/有序模型；
- 比较和细分：差异检验、聚类、判别、对应分析；
- 测量和路径：EFA/CFA/SEM/PLS-PM；
- 文本洞察：内容分析、词频/TF-IDF、情感、主题和共现；
- 产品与策略：IPA、KANO、联合分析、漏斗/关联规则、SWOT/PEST、情景和敏感性；
- 产业效率与趋势：DEA、投入产出、时间序列或预测。

### 建模方案固定格式

每次给出 2–4 个可比较方案，每个方案必须写：

`方案名称 / 研究问题 / 因变量与自变量 / 题项和数据形态 / 样本与抽样前提 / 分析步骤与软件 / 诊断与稳健性 / 失败条件与降级方案 / 结果到行动 / 推荐等级`

优先推荐“最小可行主方案 + 一个验证或补充方案”，而不是并列堆十几个模型。

## 调查实施与数据质量

调查方案必须说明总体、抽样框、抽样方法、样本量依据、预调查、问卷逻辑、调查员培训、时间/渠道、质量监控、清洗和记录保存。重点检查：

- 研究对象与样本是否匹配，是否存在便利抽样或渠道偏差；
- 筛选题、跳转、选项互斥穷尽、量表来源和反向题是否合理；
- 是否有预调查不通过预案、统一调查口径、回访/抽查、陷阱题或逻辑一致性检查；
- 缺失值、重复、异常时长、矛盾回答和剔除样本是否有预先规则；
- 结论是否只适用于实际抽样范围。

信度、效度和拟合指标只作为参考证据，不能机械按一个阈值删题或宣称因果。根据题项、样本、理论和估计方法报告内部一致性、因子结构、模型假设、效应量、稳健性和限制。质量状态统一为 `pass / conditional / blocked`，具体清单见 `references/quality-gates.md`。

## 报告逻辑与写作

可按选题选择章节，不强制所有作品使用同一目录。通常应覆盖：

1. 摘要、关键词、目录和图表清单；
2. 背景、研究问题、文献/理论和研究框架；
3. 调查方案、抽样、问卷/访谈、预调查和实施；
4. 数据处理、样本结构、质量检验和描述分析；
5. 按研究问题组织的模型/文本/策略分析；
6. 结论、分对象建议、不足与展望；
7. 参考文献和可核查附录。

高分作品的可复用特征是：选题聚焦真实痛点且具有应用价值；文献真正影响问题界定和方案修正；方案完整、科学、合理、可行；调查过程可追溯；分析方法适配数据；报告逻辑清楚、图表准确易读；创新服务于问题解决，而不是新方法堆砌。

报告终审按七维自查：研究选题、文献研究、方案设计、调查实施、分析与结论、报告文本、研究创新。每一维都要写证据位置和缺口，不能只因为正文提到过就判定通过。

结论使用 `研究问题 + 数据/表图 + 结果 + 限制`；建议使用 `证据 → 责任主体 → 具体动作 → 资源/前提 → 时间 → 衡量指标`。禁止“加强宣传、提高质量、扩大投入”等无对象、无步骤、无指标的空话。

## 规则核验与提交审计

把规则分成三层：

1. **官方硬规则**：当年度组委会通知；
2. **赛区/组别规则**：对应赛区、组别和提交系统要求；
3. **论文经验**：本地论文、培训课件和获奖作品中反复出现的做法。

发生冲突时以最新官方通知为准，并记录来源、发布日期和核验日期。不要把“两万字”“65 页”“查重 20%”“匿名”“正文与附录分开”等历史或赛区要求写成永远适用的规则。

提交前按 `references/quality-gates.md` 审计：组别和截止时间、格式/页数/命名、正文与附录、匿名、地图、查重、引用、AI 说明、原始/脱敏数据、脚本、调查记录和文件可打开性。

## 快速自检

在声称“完成”前回答：

- 我是否知道当前阶段和下一闸门？
- 每个关键结论是否能追溯到真实数据、代码或文献？
- 是否把论文经验误写成官方规则？
- 是否有不适配的数据、抽样、模型或图表？
- 是否明确了不确定性、限制和下一步？
- 是否完成匿名、地图、查重、AI、附录和文件提交审计？
